2.2 Objetivos
1.- Comprender los conceptos básicos de AzureDevOps como lo son la creación y administración de
repositorios, commits y las ramas.
2.- Desarrollar habilidades prácticas en el uso de AzureDevOps para el control de versiones, incluyendo
la resolución de conflictos, la gestión de ramas y la recuperación de versiones anteriores.
3.- Entender la importancia del control de versiones en el desarrollo de software y cómo AzureDevOps
puede ayudar a los equipos a colaborar de manera más efectiva y garantizar la calidad del código.
2.3 Resumen
Azure DevOps es un conjunto de herramientas y servicios en la nube, proporcionados por
Microsoft, que ayudan a los equipos de desarrollo a planificar, colaborar, construir, testear y
desplegar aplicaciones de manera más eficiente y rápida. Incluye herramientas como Azure
Boards, Azure Repos, Azure Test Plans, Azure Artifacts y Azure Pipelines, y permite a los
equipos de desarrollo trabajar juntos en un entorno integrado y automatizado para acelerar
la entrega de software de alta calidad. Azure DevOps es una solución en la nube, lo que
ofrece una alta disponibilidad y escalabilidad, permitiendo a los equipos trabajar de manera
más eficiente y efectiva sin tener que preocuparse por la infraestructura subyacente.
2.4 Palabras clave:
Azure DevOps, Herramientas de colaboración, Entrega de software, Microsoft,
Infraestructura en la nube.
2.5 Introducción
La historia de Azure DevOps se remonta a los inicios de Microsoft Visual Studio Team
System (VSTS) en 2005, una suite de herramientas para el ciclo de vida de desarrollo de
software que incluía funciones para planificación, gestión de código fuente, construcción,
pruebas y seguimiento de errores.
En 2018, Microsoft anunció el rebranding de VSTS a Azure DevOps con el objetivo de ofrecer
una solución integral para el ciclo de vida de desarrollo de software, que se integra con otros

2.6 Materiales y Metodología
Materiales:
1.- Computadora o dispositivo con acceso a Internet.
2.- Cuenta de Azure DevOps o acceso a una cuenta existente.
3.- Proyecto en Azure DevOps creado o acceso a un proyecto existente.
4.- Repositorio de código fuente (por ejemplo, Git) configurado en Azure DevOps.
Metodología:
Definir los requisitos del proyecto: Antes de comenzar a utilizar Azure DevOps como sistema de
control de versiones, es importante definir los requisitos del proyecto, como el tipo de proyecto,
el tamaño del equipo, las ramas del repositorio.
Crear un proyecto en Azure DevOps: Inicia sesión en Azure DevOps y crea un nuevo proyecto
o accede a un proyecto existente donde se almacenará el código fuente y se realizará el control
de versiones.
Configurar el repositorio de código fuente: Selecciona el tipo de repositorio de código fuente que
deseas utilizar, como Git, y configúralo en el proyecto de Azure DevOps. Puedes crear ramas
principales, como la rama "master" o "main", y ramas secundarias para el desarrollo de
funciones o correcciones de errores.
Clonar el repositorio: Clona el repositorio en tu computadora local utilizando herramientas de
control de versiones, como Git, para que puedas realizar cambios en los archivos de código
fuente.

Marco Teórico:
El sistema de control de versiones es una herramienta fundamental en el desarrollo de software
que permite gestionar y controlar los cambios realizados en el código fuente y otros artefactos
durante el ciclo de vida de desarrollo de un proyecto. Azure DevOps es una plataforma de
desarrollo colaborativa de Microsoft que proporciona una solución integral para la gestión de
proyectos y el control de versiones. A continuación, se presenta el marco teórico relacionado
con el sistema de control de versiones Azure DevOps:
Control de versiones y gestión del código fuente: El control de versiones es un sistema
que permite rastrear, registrar y controlar los cambios realizados en el código fuente de
un proyecto. En este marco teórico, se pueden presentar diferentes métodos de control
de versiones, como el control centralizado (como Subversion) y el control distribuido
(como Git), y explicar cómo Azure DevOps utiliza Git como su sistema de control de
versiones predeterminado.
Ramas y flujo de trabajo: Las ramas en el sistema de control de versiones permiten
organizar y gestionar las diferentes líneas de desarrollo de un proyecto. Pueden
explicarse conceptos como la rama "master" o "main" como la rama principal y otras
ramas secundarias utilizadas para el desarrollo de nuevas características, corrección de
errores o pruebas. Además, se pueden presentar diferentes estrategias de flujo de
trabajo, como GitFlow, y cómo Azure DevOps proporciona herramientas para gestionar
estas ramas y facilitar la colaboración en equipo.
Integración y entrega continuas (CI/CD): Azure DevOps no solo se limita al control de
versiones, sino que también proporciona capacidades de integración continua y entrega
continua (CI/CD). En este marco teórico, se pueden describir los conceptos y beneficios
de la integración continua, donde los cambios se integran y se prueban
automáticamente, y la entrega continua, donde las versiones del software se despliegan
automáticamente en entornos de desarrollo, pruebas y producción.

Comprender los conceptos básicos de Azure DevOps es fundamental para utilizar de manera
efectiva esta plataforma en el control de versiones. Mediante el conocimiento de cómo crear y
administrar repositorios, realizar commits y gestionar ramas, se establece una base sólida para
el control de versiones en Azure DevOps. Esto permite a los desarrolladores y equipos de
proyecto utilizar las funcionalidades principales de la herramienta y aprovechar al máximo sus
capacidades.
Desarrollar habilidades prácticas en el uso de Azure DevOps para el control de versiones implica
adquirir destrezas en la resolución de conflictos, la gestión de ramas y la recuperación de
versiones anteriores. Estas habilidades son esenciales para mantener la integridad y la
consistencia del código fuente en un proyecto. Con Azure DevOps, los equipos pueden
colaborar de manera efectiva, asegurando que todos los cambios realizados sean
adecuadamente registrados, revisados y fusionados, lo que contribuye a la eficiencia y la calidad
del desarrollo de software.
El control de versiones desempeña un papel crítico en el desarrollo de software, ya que permite
a los equipos gestionar y controlar los cambios realizados en el código fuente a lo largo del
tiempo. La comprensión de la importancia de este control y cómo Azure DevOps puede
respaldar este proceso es esencial para garantizar la calidad del código y facilitar la colaboración
efectiva entre los miembros del equipo. Azure DevOps proporciona herramientas y
funcionalidades que permiten a los desarrolladores trabajar de manera coordinada, monitorear
el historial de versiones y recuperar versiones anteriores cuando sea necesario, mejorando así
la eficiencia y la fiabilidad del desarrollo de software.
